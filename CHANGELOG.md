# Changelog

What a consumer needs to know when it moves its pin. Each entry names the issue that made the change; a revision is whatever `main` held after that issue's pull request merged. Changes that alter only this repository's process or documentation get no entry.

**Breaking** marks a change that can stop a consumer building or change what its game does. Everything else is additive.

## Unreleased

- `window_size::WindowSizeLogPlugin` logs `Window: {W}×{H} physical pixels at scale factor {S}` at `info` each time the primary window's size and scale factor hold for 500 ms, so a game's log says what size its table renders at. It times the hold with Bevy's `Time<Real>` and reads only the window marked `PrimaryWindow`. Add it to your windowed table; with no primary window, as at the seat, it logs nothing. It is Arkham's own log, moved from its tabletop health plugin, with the same line (#83).
- **Breaking:** every workspace package needs Rust 1.100.0. Each one's `rust-version` is `1.100.0`, so Cargo refuses to build it with an older compiler, and this repository's `rust-toolchain.toml` pins 1.100.0. Move your own toolchain to 1.100.0 when you move your pin of this repository (#84).
- **Breaking:** `Seat::respond` returns `Result<Value, seat::Exited>` instead of `(Value, bool)`, so an in-process test cannot go on answering requests after its table has exited. Every response but `exited` is `Ok`, `bye` included. The request that finds the exit is `Err(Exited)`, whether its own steps made the table exit or the exit came before it, and so is every later request, which acts on nothing. `Exited`'s `Display` is the reason: the game's own when it refused play, and otherwise "The table exited (…)" with Bevy's `AppExit`. For an error exit that is the `exited` response's `error`. `exit()` and `is_error()` say how the table exited, and `response()` or `into_response()` give the `exited` line. To migrate, write `let response = seat.respond(app, line).unwrap();` for `let (response, _) = seat.respond(app, line);`, or `.0`. Where a test expects the table to exit, use `.unwrap_err()` and read `response()`. A game that calls `respond` fails to build at this revision until it migrates. Arkham, Cuba Libre and mudsong call it; Netrunner does not (searched each game's main for `.respond(` on 2026-11-17). The seat also checks for an exit before each request, not only after its own steps. So an exit written in an update the seat did not run, such as Bevy's default render-error handler quitting, is answered `exited` even to an `observe`, in batch form and on a held socket too. The protocol is unchanged (#79).
- `Game::interrupts(world, input)` lets a game name the inputs that may reach its table while it is unsettled, because they end or hurry a presentation rather than act on the game, such as its own control for skipping one. `input` is a `seat::Interrupt`: `Activate(&Name)` or `Key(&str)`, by the seat key's name. The seat asks only while something is pending, and only for `activate` and `key`; `point`, `drag` and `scroll` stay refused as busy. Everything else is checked as on a settled table: the revision, and the control a key that can commit must name. The response is the ordinary one, and the protocol is unchanged. Unless a game implements it, nothing interrupts, as before (#77).
- `move-pin` puts every manifest and lockfile back when a lockfile cannot be refreshed, as for a revision not yet pushed to GitHub, and prints which moves it made only once everything is at the revision. Before, it left the manifests moved and the lockfiles stale (#62 retro).
- **Breaking**, only for an exhaustive `match` on the seat protocol: `unfolded_seat_protocol::Request` gains `Advance { steps }` and `Status` gains `Advanced`, so `Status::ALL` holds 16. No game's main matches either type exhaustively (searched for `unfolded_seat_protocol`, `Status::` and `Request::` on 2026-11-17). The seat's `advance` request, `{"op":"advance","steps":N}`, steps the table's clock N steps of `STEP` through `Game::advance`, settled or not, and sends no input, unless the table exits first; N runs from 1 to 7,200 and any other count is refused unstepped. It takes no revision and is still served after a refusal or a miss. Its `advanced` response reports `steps` as `settle`'s does. To cross an animation's loop, ask for the loop's steps instead of counting the steps of other requests, such as `key`'s two (#62).
- **Breaking**, only for an exhaustive `match` on the seat protocol: `unfolded_seat_protocol::Request` gains `Drag` and `Status` gains `Dragged`, so `Status::ALL` holds 15. No game's main names either type (searched for `unfolded_seat_protocol`, `Status::` and `Request::` on 2026-11-17). The seat's `drag` request presses a mouse button on a named target, moves the pointer while it is held and releases it, so the table camera's right-drag orbit can be driven at the seat; the seat's rustdoc has its contract. A skipped request's error now reads "its activations, drags, keys and scrolls"; no game's main has either end of the old sentence (searched for `keys and scrolls` and `Skipped: an earlier`). `scroll` already reached the table camera's wheel, and a test now holds that (#63).
- **Breaking:** the deprecated items are gone, none of which any game uses: `unfolded_assets::AssetError` (match `unfolded_assets::Error`'s cause, or keep a sentence error of your own); the seat client's `connect`, `exchange` and `read_line` (use `Connection::open`, `Connection::send` and `Connection::request`); `count_label` (spawn your own node with a `label_anchor::LabelAnchor`); `capture::image_to_file` and its `capture::Failure` (use `capture::when_ready` and its `Missed`); and `Game::pipelines_ready`, which the seat's capture no longer asks, since it finds the render pipelines' readiness itself. `unfolded-assets` no longer depends on `serde_json`. (#68).
- **Breaking:** `unfolded_record_replacement::read` and `replace` take no error constructor. `read` returns `unfolded_record_replacement::Error`, whose `TooLarge`, `Busy`, `NotRegularFile` and `Io` you match. `replace` returns your own error, any `E: From<Error>`; `std::io::Error` and `save::Error` already convert. Delete the constructor argument, and name `E` where your closures don't fix it. The defaults no longer speak of Arkham's experiment: "The record exceeds its size limit.", "The record is busy: …" and, for `save::Error::TooLarge`, "The save exceeds its size limit." A game that wants the old sentence matches the cause and says it. `save::Error::Busy` carries the operating system's `io::Error` instead of its text, with the same words (#39).
- **Breaking:** `unfolded_assets`' functions return `unfolded_assets::Error`: `cause()` is a `Cause` to match, and `path()` is the asset, root, relative path or output it concerns. The text is unchanged and names no path. `AssetError` was deprecated here and is removed by #68. Keep a sentence error of your own if your game needs one (#39).
- **Breaking:** `seat::socket::Listener::claim` returns `socket::Unclaimed`. `path()` is the path, and `cause()` is an `Unclaimable` cause to match, such as `Answered`, `NotSocket`, `TooLong` or `Unlocked`. `to_string()` gives the text it returned before, and `cause().to_string()` the part after `Cannot listen on <path>: ` (#39).
- **Breaking:** `capture::write_image` returns `capture::Unsaved`, and `Missed::Unsaved` and `Failure::Unsaved` carry it: `Unconverted`, `Unencoded`, or `Unwritten` with the operating system's error kind. The text is unchanged (#39).
- **Breaking:** the seat client's `Connection::send` and `Connection::request` take a `check` that returns your own error, and hand it back as `Unsent::Stopped` or `RequestError::Stopped`. `send` fails with `Unsent`, and `requests` with `Unrequested`. A check that never fails names its type, such as `|| Ok::<(), Infallible>(())`. The text is unchanged. `Stopped` no longer names your error's own source: report your error from `Stopped` itself. #68 removes the deprecated `exchange` and `read_line` (#39).
- **Breaking:** `loading::font_registration` says whether a font is `Pending`, `Registered` or `Refused` by the text renderer; `font_registered` is unchanged. An empty required set's failure reads "The required asset set is empty." instead of Arkham's "The required artwork set is empty. Play cannot start." (#39).
- The check recorder's source fingerprints are labelled `unfolded-check-source-v1`, so they differ from earlier revisions'. A record compares only its own two fingerprints, which one build computes (#39).

- `held-start` records the SHA-256 of the executable it ran, and `compare-captures` says whether two recorded captures came from the same executable. `move-pin --align` moves pins that disagree, such as a manifest left behind at an earlier move (#38 retro).
- `capture::windowless(plugins)` gives a host's plugins no window, no exit for the lack of one and no window event loop: write `capture::windowless(DefaultPlugins.set(…))` and delete your own `.set(capture::no_window())` and `.disable::<WinitPlugin>()`. Whether rendering is pipelined stays yours. `unfolded-tabletop` with `render` now enables Bevy's `bevy_winit` and `x11` features, as every game already does (#38).
- `capture::OnSurface` marks a camera that renders the windowless surface's image, beside the camera `install` names, which stays the only default UI camera; each camera keeps its order, viewport and clear colour. The mark does nothing without a surface, so put it on the camera where you spawn it, and delete your own system that retargets a second camera (#38).
- `capture::when_ready` is the seat's ready-then-capture loop, for a capture with no seat as well: it waits, within your deadline, for the render pipelines and a condition of yours to hold on two consecutive frames, then writes the file. Its `capture::Missed` says whether no picture was asked for (`Unready`) or none came back (`Incomplete`), each with `Ended::Stopped` or `Ended::Deadline`, apart from `Unsaved`. `image_to_file` was deprecated in its favour, and #68 removes it. The seat's `capture` request is unchanged (#38).
- `move-pin`, run from a checkout of this repository, moves every pin of it in a game's tracked manifests to one revision and refreshes the game's tracked lockfiles. It refuses pins that disagree (#37 retro).
- `camera::TableCameraPlugin` gathers the table camera's input itself: keys, mouse buttons, wheel, primary window and frame time, by Bevy's `Time` or `Time<Clock>` for a game clock of your own. It finds itself whether the pointer is over a UI node (the hover map) and whether keyboard focus is on a `ui_widgets::Button`; mark a UI node that stands for something in the scene, such as a count over a token, `InScene`, and the pointer over it still zooms and drags. To adopt it: insert your `Orbit`, mark your camera `TableCamera`, write `TableFacts` (`blocks_camera`, `takes_view_keys`, `takes_wheel`, and `scene`, a `Scene::Within` rectangle for a pointer region of your own) in a system before `TableCameraSystems`, read `Navigation` after it, and delete your own system. WASD pan stops only when the table blocks the camera, as in every game's system before. `Orbit::drive` takes the same input as plain values in a `camera::Input`, for tests. `Orbit::step`, `FrameInput` and `Capture` still work (#37).
- `camera::Framing` names a target and distance. `camera::PITCH`, `camera::DISTANCE`, `Pose::DEFAULT_YAW`, `Pose::DEFAULT_PITCH`, `Pose::at`, `Pose::direction` and `Pose::transform` make the limits and default pose readable, `Orbit::home` reads where Home returns, and `Orbit::set_home` changes it without moving the camera. `camera::KEYS`, `PAN_KEYS` and `VIEW_KEYS` are the keys the camera reads, and `camera::SEAT_KEYS`, under `seat`, the same keys for a seat key table; `SeatKey` and `Logical` are `Clone` and `Debug`, so a table can join them to its own (#37).
- **Breaking:** `Orbit::update_follow_target` takes an `Option<Framing>`; write `Some(framing.into())` for a `(Vec3, f32)`. `Orbit::new`, `with_home` and `focus` take anything that converts into a `Framing`, a `(Vec3, f32)` included. `unfolded-tabletop` with `render` now enables Bevy's `bevy_ui_widgets` feature (#37).

- `held-start --clean` refuses to launch from a working directory that is not a Git working tree or has changed tracked files, so a "before" case records only a clean revision (#36 retro).

- **Breaking:** `unfolded_record_replacement::save` owns a game's save record: its envelope, checksum, write baseline, unchanged shortcut, previous-record validation and recovery. To adopt it, implement `save::Format` (payload, identity, accepted identities, validity, limit), choose a `save::Write` for each write, word each `save::Error`, and delete your own envelope. Your saved format changes with it: saves written before it are refused and left on disk, and nothing migrates them. `replace`, `read` and `previous_path` are unchanged; `lock_path` and `archives` name the lock and restart archives, so tests need not spell them (#36).

- Deprecated `count_label`, and the seat client's `connect`, `exchange` and `read_line`, which no current consumer calls, and which #68 removes. Use `label_anchor::LabelAnchor` on a node of your own, and `Connection::open`, `Connection::send` and `Connection::request` (#56).
- `held-start --help` and `compare-captures --help` describe each tool in full (#56).

## Before 2026-11-16: what still matters

- **Breaking:** the re-exports `unfolded_tabletop::random`, `unfolded_tabletop::hover`, `unfolded_tabletop::record_replacement`, `unfolded_tabletop::assets` and `unfolded_tabletop::seat_client` were removed. Name each mechanism by its own package, such as `unfolded_random::SeededRandom`. The last revision of `main` that has them is `8080f29` (#31).
- `seat::start` runs a game's whole seat start in batch and held form. The separate calls (`detached`, `launch`, `detach`, `announce`, `Seat::open`, `Seat::admit`, `Seat::serve`, `Listener::serve`) still work, so a game that keeps its own sequence still builds. They are not deprecated: `start` is built from them, and games' tests call `Seat::admit` and `Seat::serve` (#32).
- `Game::pipelines_ready` is deprecated: the seat finds whether the render pipelines are ready itself, through `capture::Pipelines`. A capture also waits for the deprecated method, so a game that still answers it keeps working. Every response of a seated table gained `revision`, `settled` and `pending` fields; no other field or wording changed (#33).
- The seat protocol's vocabulary moved to `unfolded-seat-protocol`. The wire did not change, so a seat and a client at different revisions keep talking (#34).
- `label_anchor` keeps any caller-owned UI node over a world anchor. `count_label::spawn` now adds a `LabelAnchor`, and `CountLabelPlugin` installs `LabelAnchorPlugin`; a game may add both plugins, in either order (#35).
- **Contract:** the numbers a `SeededRandom` state produces are part of every consumer's saved games. `random/tests/random.rs` pins numbers recorded from Arkham; any change to them is breaking.
